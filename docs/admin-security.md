## Authentication and authorization

`/admin` is lazy and available only inside the existing ready session. Explicit login always starts in ordinary Reals; restored sessions may still open the direct administrative URL. `AdminGate` uses `AdminAccess` to read `GET /api/admin-auth/status`, submit the six-digit string to `POST /api/admin-auth/verify`, then confirm the returned grant with status before mounting the privileged backoffice. Diagnostics is an additional protected read after MFA, never an MFA substitute. There is no enrollment, QR, recovery, local TOTP check or local eligibility allowlist.

The owning [handoff](../../reals-backend/docs/web-admin-integration-handoff.md), [operator runbook](../../reals-backend/docs/admin-auth.md), [API](../../reals-backend/docs/commons/api.md#administrative-authentication) and [OpenAPI](../../reals-backend/docs/commons/openapi.yaml) are authoritative. The verified Firebase UID/email, active local account, Google provider, Web App Check ID, factor and grant bindings are checked by Spring on every privileged call. Client context checks improve guidance only; they create no authority.

Normal users retain password and Google sign-in and existing persistence/tab policy. The Firebase adapter reads refreshed `getIdTokenResult` provider and `authTime`; password sessions are instructed to explicitly sign out and use Google with the same Reals account. Google reauthentication calls `reauthenticateWithPopup` synchronously from a deliberate click, then refreshes and checks the resulting token's provider and authentication age (strictly less than 300 seconds, no future time). A refresh alone is never treated as reauthentication. The provider must still be `google.com`; otherwise the user is guided to sign out/sign in. Live claim behavior must still be verified with Firebase.

`auth/appCheck.ts` uses the real Firebase App Check SDK, one instance per Firebase app, automatic refresh and typed token acquisition. Public settings are `VITE_FIREBASE_APP_CHECK_PROVIDER=enterprise` (preferred) or `v3`, and `VITE_FIREBASE_APP_CHECK_SITE_KEY` matching the registered provider. Missing configuration, attestation failures and empty tokens fail closed. The official SDK Debug Provider is opt-in through `VITE_FIREBASE_APP_CHECK_DEBUG=true`, exclusively with Vite DEV, PROD=false and exact hostname localhost/127.0.0.1. It sets `self.FIREBASE_APPCHECK_DEBUG_TOKEN=true` before initialization; production and other hosts never enable it. The application never copies, persists or logs the generated debug credential; the official SDK manages its own browser credential storage and local console message. There is no backend verification bypass. See the [local workflow](local-development.md#local-web-app-check-debug-provider). App Check is sent on backend API requests including public protected resources, except the backend's ping/local-dev exclusions. The injected synthetic test transport is not production attestation.

Grants live exclusively in a private in-memory field, outside UI snapshots. `X-Reals-Admin-Grant` is sent only to admin/admin-auth routes. No grant is written to storage, cookies, URLs, logs or analytics. Server `expiresAt` is an absolute limit: equality retires the local grant/data; it never renews. Ordinary visibility changes and visual gate remounts preserve the session-owned grant and its original deadline. Foreground return rereads status without unmounting an already-authorized backoffice; a still-valid grant does not require recent Google reauthentication or another TOTP. Actual pagehide, explicit administrative revocation/logout, identity replacement, loss of tab ownership and operational-session invalidation retire local authority. Internal mode switches between Reals and Admin retain the in-memory grant and original deadline, while disposing private views and suspending privileged requests. No grant survives a full document reload. Transient status/network failure blocks privileged UI but retains only the unexpired credential for status recovery; 401/403 or a negative status retires it.

Explicit administrative revocation, actual pagehide and ordinary logout attempt revoke using the captured identity and grant, with a five-second abort deadline. Local retirement is synchronous and unconditional. Logout waits for that attempt before Firebase sign-out. Failed revocation displays a safe operator warning; expiry remains the server safeguard. Closing a document, losing ownership or losing connectivity cannot guarantee server revocation. No unload beacon carries credentials or grants.

Requests disable redirects and caching for both administrative path families and never retry TOTP or admin writes, including INVALID_TOKEN. Administrative 401/403 clears grants/data; invalid Firebase sessions and account restrictions retain existing domain handling. Other failures distinguish invalid/replayed codes, operator configuration/eligibility, App Check, unavailable verification and network errors. Retry-After creates an advisory absolute cooldown retained through status refresh/reauthentication; verification remains an explicit action. Server eligibility/lockout is always authoritative. Backend response text is never used to expose diagnostics or secrets.

## Administrative invariants and response-installation review

| Path | Invariant and handling |
| --- | --- |
| Entry/status | Current identity generation and access revision only; boolean DTO validation; first entry requires an in-memory grant and backend `grantValid=true`. Foreground revalidation keeps an already-confirmed grant/panel mounted while pending; denial removes it. Transient failures block UI, retain only the unexpired grant for retry and respect Retry-After. |
| TOTP verify | Synchronous busy exclusion, string/leading-zero preservation, no local TOTP validation; context freshness checked again before POST; no automatic retries. Malformed/expired grant responses fail closed. |
| Grant installation/status confirmation | Token and absolute deadline installed together; confirmation must succeed before private data can load. Grant stays out of snapshots. |
| Privileged reads/writes | Session readiness/domain restrictions plus current grant required. Existing AdminStore mutation exclusion/reconciliation is unchanged. Obsolete identity/grant responses cannot install data or retire a newer grant. |
| Reauthentication | Synchronous popup, no retained grant, same current identity and owned tab checked after awaits; unsuitable provider/freshness fails with sign-in guidance. |
| Expiry/denial/revocation | Abort access work, retire token/timer and unmount private stores/media; stale finalizers cannot reopen admin UI. Timers only remove local permission, never create server authority. |
| Logout/exit | Capture owned identity/grant for bounded revoke, clear locally first, then Firebase logout even on failure; actionable warning persists through logout. |
| Identity/tab/session disposal | Abort/revision ownership rejects late responses. SDK token acquisition is raced against abort so canceled requests cannot later reach fetch. Listeners/timers clean up only their resources; no business transition is invented. |

## Privacy and media

Admin responses and drafts live only in an owned in-memory store. No localStorage, sessionStorage, IndexedDB, persistent application cache, telemetry or report URLs in history are introduced. Route exit, logout, identity replacement, ownership revocation and page disposal abort requests and discard state. Browser history retains only `/admin`, never selected IDs or evidence. Signed media fields accept HTTPS (loopback HTTP only in development); embedded URLs in report text are never links. React renders all content as text.

Photo previews use no-referrer images; thumbnails are lazy. Audio is created only after explicit activation, with `preload=none`, and is released on background/unmount. The admin mount installs a no-referrer document policy for media requests and removes it on disposal. Audio errors require manual report refresh to renew links. Backend/media/CDN must independently deliver private `Cache-Control: no-store`, correct MIME types and suitable cross-origin policy, and exclude signed URLs/evidence from access logs and telemetry. Browser/OS caches and devtools are not controlled by application memory cleanup. Verify actual CDN responses before release.

| Path | Invariant and reconciliation |
| --- | --- |
| Authorization | Only validated diagnostics HTTP 200 permits lists; 401/403 clears all admin data. No background polling. |

| Appeal source report | Atomically replace appeal rows/selection with an in-memory report context. Only the selected appeal's exact source link can open it while authorized, idle and unblocked. | Success | Validate/install confirmed response; reconcile via GET. Appeal public DTO is parsed independently of queue items. Confirmed success survives later refresh failure. No optimistic decisions or other-user session changes. |
| Conflict/uncertain write | Clear actionable detail and block decisions until a successful authoritative GET. Never replay POST. Photo conflicts refresh queue; appeals use pending list, never an invented appeal-detail endpoint. ## Pagination and scope

Photos: backend returns at most 100 pending entries, oldest first. Local pages show 20 of that capped response; nothing beyond 100 is fetched. Reports: full-list retrieval and backend in-memory filtering remain authoritative. Local pagination reduces neither network nor database work. No page/size/offset/cursor parameters are invented. True server pagination is future backend work. Appeals also use local 20-item pages. Diagnostics is read-only, manually refreshed, without graphs or polling.

No manual report creation, user/role management, suspended-user appeal UI, deployment resources, backend or Android changes are included.

## Confirmed Reals / Admin mode policy

The operator explicitly chose grant retention on internal mode changes. **Switching the display mode is not terminating administrative authorization.** This section supersedes the older route-exit retirement policy in the historical lifecycle investigation above.

Normal sign-in, including Google sign-in by the administrator, enters regular Reals. In Account, `useAdminEligibility` confirms the actual Firebase ID-token provider through `googleContext`, requires a ready ACTIVE ordinary account and a strictly HTTP-200, well-formed `GET /api/admin-auth/status` with `configured=true`. `grantValid=false` is acceptable for this entry: eligibility is only a UI hint. Linked providerData, account emails/UIDs, client flags and stored grants do not determine eligibility. Password sessions never query this endpoint for the entry. Non-admin Google accounts, 403, unconfigured/malformed status and failed requests show no administrative entry or placeholder. Backend/Firebase invalidation and context changes retire old confirmations; stale requests cannot restore them. Eligibility rechecks on Account entry and foreground return. No eligibility result creates authority.

`ReadySession` owns the existing Home history hook for both active-profile and setup surfaces. Its `admin` destination maps to `/admin` with same-document history APIs; ordinary destinations map to `/`. Back/Forward use the same owner/trail and navigation guards as Account, notifications and profile questions. Stale account entries cannot restore private screens. The Home/profile/questions hierarchy remains responsible for its forms and nested state. A browser reload/new operational owner still starts with no grant. A normal login from a former `/admin` URL resets the URL to Reals before showing ready content.

Selecting Administration mounts AdminGate. Initial access still requires Google/TOTP plus confirmed backend grant status. **Volver a Reals** returns to Account, unmounts AdminStore/media and cancels visual work with `AdminAccess.suspendView`; it never calls leaveAdmin or revoke. The token, expiry timer and absolute backend expiresAt remain in SessionController memory. Returning mounts a checking gate and revalidates status before private reads; a valid grant does not require another TOTP or a five-minute-fresh Google login. Only new issuance requires recent Google authentication. No timer is restarted or extended by switching, eligibility or status reads. Expiry clears the token even while ordinary Reals is visible.

A private display-mode boundary and epoch in SessionController additionally prevent `/admin/**` calls from the normal-user surface and reject responses from an earlier admin visit, even if the same token is retained. These fields restrict requests; they never establish eligibility or grant authority. No administrative store or private media is retained behind hidden normal-user DOM. Ordinary Account only reads the non-sensitive eligibility status.

**Cerrar acceso administrativo** is a separate explicit backoffice action: retire locally, attempt bounded revoke, then consult status only if the same session/admin visit still owns the result. Ordinary logout also revokes a retained grant before Firebase sign-out. SessionController owns pagehide handling in every mode, so switching to normal Reals cannot remove that security boundary. Identity replacement, terminal session invalidity and ownership-lease revocation still retire all authority. No backend/Android, Auth initialization, tab-ownership policy, deployment or App Check configuration was changed.
